Getting the site into Google

The page is live, but Google has never crawled it — a brand-new github.io address with no inbound links is invisible by default. Here is everything that changes that, in the order it needs doing.

index.htmlReplaces the existing file

What to do

  1. Commit the files

    In the repository, open index.html, select all, paste in the new version, and commit to main. Then Add file → Upload files, drop the other four in the root, and commit again.

    GitHub Pages rebuilds in a minute or two. Confirm it worked by loading https://nse-conference.github.io/robots.txt in a browser — if you see the text, everything else is in place too.

  2. Add the site to Google Search Console

    Go to search.google.com/search-console and sign in with the Google account you want to own this. Add property offers two boxes — choose URL prefix, on the right.

    Enter the address exactly: https://nse-conference.github.io/

    Why not the other box

    The Domain option verifies through DNS records, and the DNS for github.io belongs to GitHub, not to you. It cannot be made to work here.

  3. Prove you own it

    Google offers several methods. The HTML file one is the least fiddly for a Pages repository:

    • Download the file Google gives you — something like google1a2b3c4d5e6f7890.html.
    • Upload it to the repository root and commit, exactly as in step 1.
    • Check it loads at https://nse-conference.github.io/google1a2b….html, then click Verify.

    The HTML tag method works equally well if you prefer: paste the <meta name="google-site-verification" …> line into index.html just under the <title>. Whichever you use, leave it in place afterwards — removing it un-verifies the site.

  4. Submit the sitemap

    In the left menu: Sitemaps → type sitemap.xml → Submit. Status should read Success within a day.

  5. Ask for the homepage to be crawled now

    Paste https://nse-conference.github.io/ into the Inspect any URL bar at the top of Search Console, then click Request indexing. This puts the page in a priority queue — usually hours to a few days rather than weeks.

  6. Get other sites to link to it

    This is the step that actually decides how quickly the site is found and how well it ranks. Google discovers and trusts pages mostly by following links from pages it already trusts. A sitemap says this page exists; links say this page matters.

    decisive strong worth doing
    The series page at Stanford
    Ask Matt Jackson to link “Luxembourg · 2026” on web.stanford.edu/~jacksonm/NSE.html to your address. That page already ranks for this conference, on a domain Google trusts deeply. This single link is worth more than everything else on this list.
    uni.lu
    A Department of Finance / FDEF news item and an entry in the university events calendar. Strong domain, and topically exactly right.
    Organisers' own pages
    Your staff page, and the personal academic pages of the local and series organisers. Easy to arrange and each one is a real, relevant link.
    Economics conference listings
    INOMICS, WikiCFP, the AEA calls-for-papers listing, RePEc / NEP announcements, EconBiz. These are where economists actually look, so they bring visitors as well as links.
    FNR
    If the fund lists supported events, ask to be included — the logo is already on the page.
    Announcements
    The mailing list, LinkedIn, X, Bluesky. Social links count for little on their own, but they get the address in front of people who run sites that do count. The preview image makes those posts look like a real conference.
    One thing to avoid

    Skip paid links and the “submit your site to 500 directories” services. They are the one category of link that can actively damage a site's standing.

Checking whether it worked

The fastest test — type this into Google. Nothing returned means not indexed yet; the homepage returned means done.

site:nse-conference.github.io

In Search Console, the Pages report is the fuller picture. Discovered — currently not indexed means Google knows about the page but hasn't judged it worth crawling; that is exactly what links fix.

Realistic timing: a few days if step 5 goes well, up to about three weeks for a new site with few links. If nothing after two weeks, request indexing again and chase the Stanford link.

Ten more minutes, if you have them

Bing Webmaster Tools lets you import the property straight from Search Console in a couple of clicks. Worth it because Bing's index feeds Copilot and several AI assistants, which is increasingly how people find conferences.

Two things about the page itself

Not changed — these are yours to decide.

The submission deadline has passed

The countdown in the hero already flips to “Submissions for the 2026 conference are now closed”, but Key dates still presents 31 July as the live deadline, and both large buttons still read “Submit a paper”. Once Google indexes the page, whatever it says is what prospective attendees see — worth pointing the page at notifications and registration instead.

The venue address in the structured data

I used the university's general Belval address — 2, place de l'Université, L-4365 Esch-sur-Alzette. If the conference sits in a specific building, change it in the <script type="application/ld+json"> block near the top of index.html; Google uses it for the map and location shown in event results.
